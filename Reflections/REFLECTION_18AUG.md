## Coordinate System and Motion

I also learned to use the coordinate system to define or specify a graphical object’s position on the screen. The square has an x and y coordinate. We can adjust its position by changing the value of the x and y coordinate.



Furthermore, I learned that the idea behind motion is achieved when we continually update a graphical object’s coordinate and then redraw or display it on the screen. For instance, we can update the square’s x coordinate to move it to the left or right. We can also update the square’s y coordinate to move it up or down.



With the above knowledge, I can now understand that motion is related to coordinates. From that understanding, I can conclude that we cannot achieve motion without understanding coordinates. As a result, we must first know the square’s position before we can update it.

## Logic Before Coding

I realized the most valuable tip concerning the logic before coding in the lecture during the today’s class, allowing to successfully engage in developing the right programs. The idea was not to start writing code immediately but to first understand what exactly one wants the program to accomplish and how it should be done.

First of all, in order to create a “moving” form, one has to define the notion of something that moves and decide how exactly it will be done – for instance, define this form’s coordinates or state. After conceptualizing these elements, it may be helpful to write them down or illustrate them with several drawings. After this step, anyone can easily write a computer program in Java depicting a moving form, simply following the logic one has already created.

What has been said above could be applied not only to computer graphics but to any field where one wants to build a computer program. The most essential notion I have got today was that programming may not necessarily mean coding but may often imply algorithmization, or developing the right algorithms to follow.
